# ZipSearch

**Поиск и проверка текстовых и структурированных записей внутри ZIP-архивов без массовой распаковки.**

ZipSearch — локальный терминальный инструмент для поиска по неоднородным данным в ZIP-файлах: выгрузкам, журналам, электронным таблицам, базам SQLite и вложенным архивам. Он читает элементы архива напрямую, а результаты предоставляет через CLI и curses TUI с ограниченным потреблением ресурсов — без создания постоянного дерева распакованных файлов.

Интерфейс, рассчитанный на клавиатуру, показывает архив, элемент, результаты и сведения о записи в одном представлении для быстрой проверки.

ZipSearch — духовный преемник `awerpars`: идеи и опыт более раннего проекта со временем оформились в эту независимую реализацию.

## Зачем он нужен

Большие коллекции архивов неудобно проверять вручную. Распаковать всё ради одного значения — значит занять дополнительное место, потратить I/O и затем убирать временные файлы. ZipSearch находит ZIP-файлы, читает подходящие элементы и показывает результаты в CLI и TUI.

> При чтении ZipSearch всё же распаковывает данные. «Без массовой распаковки» означает, что коллекция архивов не разворачивается в постоянное дерево каталогов. Некоторые обработчики используют автоматически удаляемое временное хранилище; см. [Поведение хранения](#поведение-хранения).

## Кратко

| Область | Возможности ZipSearch |
| --- | --- |
| Поиск | LITERAL, регулярные выражения и нормализованный token-aware SMART-поиск |
| Данные | Текстовые элементы, строки SQLite, строки листов XLSX, вложенные ZIP |
| Проверка | Дерево архив → элемент → результат, панель DETAIL, проверка центрального каталога |
| Операции | Include/exclude glob, фильтры расширений, контекст, смена корня, экспорт, отмена |
| Контроль | Ограничения на элементы, размер, развёрнутый размер, коэффициент сжатия и вложенность; сообщения о восстанавливаемых проблемах |

## Установка

Требуется Python **3.10 или новее**. У ZipSearch нет сторонних runtime-зависимостей.

```console
python -m pip install .
zipsearch --version
```

Для разработки из рабочего дерева:

```console
python -m pip install -e . pytest ruff
```

Команда `zipsearch` без аргументов открывает TUI, только если и стандартный ввод, и стандартный вывод являются терминалами. В скриптах используйте явную подкоманду.

## Быстрый старт

```console
# Интерактивный TUI; корнем может быть каталог или один ZIP
zipsearch tui ./archives

# Обычный LITERAL-поиск (по умолчанию без учёта регистра)
zipsearch search ./archives 'customer@example.com'

# SMART: поиск по человеку/телефону с учётом пунктуации, регистра и порядка слов
zipsearch search ./archives 'Глеб Скрепкин +79087562342' --smart

# Регулярное выражение, контекст и JSON Lines
zipsearch search ./archives 'INV-[0-9]{8}' --regex -C 2 --jsonl > matches.jsonl

# Ограничение путей элементов и расширений
zipsearch search ./archives needle --extension csv --extension json \
  --include 'exports/**' --exclude '*backup*'

# Только центральный каталог архива, без распаковки элементов
zipsearch inspect evidence.zip --json
```

Полный справочник CLI: `zipsearch search --help`.

## Семантика поиска

| Режим | Правило отбора | Порядок |
| --- | --- | --- |
| **LITERAL** | Каждый pattern экранируется и ищется как непрерывное регулярное выражение; порядок слов важен. | Порядок сканирования архив/элемент/строка, с глобальным ограничением. |
| **REGEX** | Каждый pattern компилируется как регулярное выражение Python. | Порядок сканирования архив/элемент/строка, с глобальным ограничением. |
| **SMART** | Для каждого query pattern учитываются нормализованная фраза, tokens, префиксы и телефонные доказательства. | Результаты с более сильными доказательствами идут первыми глобально. |

По умолчанию в CLI используется LITERAL, в TUI — SMART. `--smart` и `--regex` взаимоисключающие. Поиск не учитывает регистр, если не задан `--case-sensitive`; `--ignore-case` явно выбирает поведение по умолчанию.

### SMART-сопоставление

SMART применяет NFKC-нормализацию; при поиске без учёта регистра сворачивает регистр и русские `ё` в `е`; пунктуацию считает разделителями, а последовательности пробелов объединяет. Редакционное расстояние и догадки об опечатках не применяются.

Для многотокенного запроса SMART ранжирует: нормализованное совпадение фразы, затем записи со всеми tokens в любом порядке, безопасные совпадения по префиксу и затем полезные частичные token-совпадения. Поэтому запись может остаться в выдаче, если совпала лишь часть многословного запроса. В компонентах, похожих на телефон и содержащих не менее семи цифр, разделители игнорируются; российский номер `8xxxxxxxxxx` нормализуется к `7xxxxxxxxxx`.

Например, `Глеб Скрепкин +79087562342` может совпасть с `Игорь Скрепкин; +7 (908) 756-23-42`. Доказательства совпадения здесь — `Скрепкин` и телефон; `Глеб` остаётся видимым в запросе, но не считается доказательством.

`match_type` и `score` присутствуют в JSONL и в деталях результата. Score — внутренний сигнал сортировки, а не процент и не универсальная оценка релевантности между запросами.

## TUI

`zipsearch tui [PATH]` открывает интерфейс, рассчитанный на клавиатуру: редактируемая строка запроса, панель RESULTS, панель DETAIL и компактная строка состояния/подвал.

- **RESULTS** — дерево: архив → элемент → совпавшая запись. Сворачивание архива или элемента не меняет загруженные результаты, ранжирование или сам поиск.
- **DETAIL** показывает выбранную запись: полный исходный запрос `matched` и только те компоненты запроса, которые дали это совпадение. Для узлов дерева показываются уже доступные метаданные архива/элемента.
- Доказательства совпадения подчёркиваются; при доступности цветов curses может использоваться один сдержанный акцентный цвет. В монохромном терминале остаётся атрибутное выделение, выбранная строка сохраняет reverse video.
- Строка состояния показывает числа архивов/элементов, результаты, проблемы, workers, глубину вложенности, **S** (длительность текущего или последнего поиска) и **U** (непрерывное время работы TUI).

### Клавиатура

| Клавиша | Действие |
| --- | --- |
| <kbd>/</kbd> | Перейти к редактированию запроса |
| <kbd>Enter</kbd> | Запустить запрос; при просмотре открыть выбранный узел или результат |
| <kbd>↑</kbd>/<kbd>↓</kbd>, <kbd>j</kbd>/<kbd>k</kbd> | Навигация по результатам; при редактировании — история запросов |
| <kbd>PgUp</kbd>/<kbd>PgDn</kbd>, <kbd>Home</kbd>/<kbd>End</kbd> | Навигация по результатам |
| <kbd>Space</kbd> | Свернуть/развернуть выбранный архив или элемент |
| <kbd>←</kbd> / <kbd>→</kbd> | Свернуть / развернуть выбранный архив или элемент |
| <kbd>r</kbd> | Сменить корень (каталог или `.zip`) |
| <kbd>m</kbd> | SMART → LITERAL → REGEX |
| <kbd>c</kbd> | Переключить чувствительность к регистру |
| <kbd>f</kbd> | Открыть фильтры и ограничения |
| <kbd>x</kbd> | Показать восстанавливаемые проблемы |
| <kbd>e</kbd> | Экспортировать текущие результаты в JSONL, CSV и текст |
| <kbd>Ctrl-C</kbd> | Отменить активный поиск |
| <kbd>?</kbd> / <kbd>q</kbd> | Справка / выход |

Компоненты TUI-запроса, разделённые запятыми, становятся отдельными patterns. Смена корня сохраняет запрос и настройки, но очищает устаревшие результаты. История накапливается в течение сессии; после самой новой записи возвращается текущий редактируемый черновик.

## Поддерживаемые данные и архивы

| Категория | Поддерживаемый ввод | Обработка |
| --- | --- | --- |
| Контейнер | `.zip` | Прямой архив или рекурсивное обнаружение в каталоге; вложенные ZIP до настроенной глубины |
| Текстовые элементы | `.txt`, `.csv`, `.tsv`, `.log`, `.json`, `.jsonl`, `.xml`, `.html`, `.htm`, `.md`, `.rst`, `.yaml`, `.yml`, `.ini`, `.cfg`, `.conf`, `.dat`, `.tad`, `.cpy` | Построчное декодирование и поиск |
| SQLite | `.db`, `.sqlite`, `.sqlite3` | Строки таблиц только для чтения преобразуются в поисковые записи |
| XLSX | `.xlsx` | Строки XML листов и shared strings преобразуются в поисковые записи |

По умолчанию элементы с другими расширениями пропускаются. `--extension EXT` явно выбирает расширения; фильтры расширения, include и exclude работают с путями элементов. `auto` сначала использует UTF-8, затем CP1251; при известной кодировке передайте `--encoding CODEC`. NUL-байт в начальной текстовой пробе означает пропуск элемента как двоичного.

Вложенные ZIP-пути в CLI отмечаются `!`, например `outer.zip:inner.zip!records.txt:42`.

## Опции CLI и ограничения

### Основные параметры поиска

| Опция | По умолчанию | Значение |
| --- | ---: | --- |
| `--max-matches` | `1000` | Глобальный предел вывода/результатов |
| `-C`, `--context` | `0` | Число строк до и после текстовой записи с совпадением |
| `--encoding` | `auto` | `auto` или имя любого Python codec |
| `-j`, `--workers` | `4` | Число потоков обработки архивов |
| `--nested-depth` | `2` | Глубина вложенных ZIP; `0` отключает обход |
| `--include GLOB` | — | Требовать совпадения пути элемента или basename; можно повторять |
| `--exclude GLOB` | — | Пропускать совпавшие пути или basenames; можно повторять |
| `--extension EXT` | — | Сканировать только выбранные расширения; можно повторять |
| `--no-recursive` | off | Не спускаться ниже входного каталога |
| `--jsonl` | off | Писать объекты совпадений и итог в JSON Lines |
| `-q`, `--quiet` | off | Не выводить обычный итог и предупреждения |

### Ресурсные ограничения

| Опция | По умолчанию | Проверяется до распаковки элемента |
| --- | ---: | --- |
| `--max-member-mib` | `512` MiB | Заявленный размер одного элемента |
| `--max-total-mib` | `2048` MiB | Заявленный суммарный развёрнутый размер архива |
| `--max-members` | `100000` | Число элементов в одном архиве |
| `--max-ratio` | `200.0` | Заявленный коэффициент сжатия элемента |

В TUI доступны эквивалентные настройки: расширения, include/exclude glob, кодировка, контекст, глубина, workers, предел и те же защитные ограничения.

## Вывод, экспорт и обработка ошибок

Обычный вывод CLI имеет вид `archive:member:line: text`; контекстные строки помечаются `-` и `+`. `--jsonl` выводит JSON-объект для каждого совпадения и один итоговый объект. Обычная диагностика и итог идут в standard error. Экспорт из TUI создаёт в текущем каталоге файлы `.jsonl`, `.csv` и `.txt` с временной меткой.

Повреждённые архивы, нечитаемые/неподдерживаемые элементы, ошибки декодирования или парсинга, небезопасные пути, зашифрованные элементы и нарушения лимитов по возможности сообщаются как восстанавливаемые проблемы; остальные архивы продолжают обрабатываться. Код CLI: `0` без проблем, `1` при восстанавливаемых проблемах, `2` при неверной конфигурации, `130` после Ctrl-C.

## Поведение хранения

ZipSearch никогда не вызывает `extractall`. Обычные текстовые элементы открываются из архива и читаются постепенно. SQLite требует произвольного доступа, поэтому только такой элемент копируется во временный каталог с автоудалением и открывается только для чтения. XLSX и вложенные ZIP используют spooled временные файлы: первые 8 MiB хранятся в памяти, затем используется системная временная область. Метаданные `inspect` берутся из центрального каталога без распаковки элементов.

## Как это работает

```text
корневой путь → детерминированное обнаружение ZIP → ограниченные workers архивов
             → проверки центрального каталога → декодер/парсер элемента
             → LITERAL / REGEX / SMART и атрибуция доказательств
             → Match-записи → CLI, JSONL или дерево/detail/export TUI
```

Обнаружение каталогов не следует по символическим ссылкам на каталоги. Сканирование архивов использует пул потоков фиксированного размера и держит в очереди не более двух окон workers. SMART-результаты сохраняются и сортируются ограниченным top-N процессом: более сильное позднее совпадение может вытеснить слабое раннее.

## Производительность

Скорость зависит от числа архивов, сжатого и развёрнутого размера, форматов элементов, задержки хранилища, режима запроса, фильтров, коэффициента сжатия и числа workers. В репозитории есть небольшой воспроизводимый smoke benchmark; это не заявление о производительности:

```console
python benchmarks/benchmark.py
```

Для запуска сгенерированного функционального набора через публичный CLI:

```console
python benchmarks/validate_realistic_dataset.py
```

<summary>Практические замечания</summary>

Фильтры extension/include/exclude позволяют не декодировать нерелевантные элементы. Увеличение `--workers` может помочь на подходящем хранилище при множестве архивов, но также повышает параллельные I/O и распаковку. Повышение лимитов размера или сжатия — решение о доверии к входной коллекции.

## Ограничения

- Поддерживается только ZIP-контейнер.
- Зашифрованные ZIP-элементы пропускаются; ввод пароля не реализован.
- Обработка XLSX читает значения листов, но не форматирование или формулы как табличное приложение.
- SQLite и XLSX создают временные данные, как описано выше.
- Автоопределение текста ограничено UTF-8 с запасным CP1251; для других известных кодировок используйте `--encoding`.
- Защитные проверки снижают риск вредоносных архивов, но не заменяют изоляцию ОС для недоверенных данных.
